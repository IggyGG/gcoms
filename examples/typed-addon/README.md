# A typed addon with Rust and TypeScript clients

`src/lib.rs` defines a query and a resumable operation. The same contract builds
for native Rust and `wasm32-unknown-unknown`. The server uses the encrypted file
journal; it never stores request arguments. Supply its wrapping key from your
host's secret management, as an owner-only file containing exactly 32 bytes.
The socket, journal and secret must have a private parent directory.

```sh
cargo run -p gcoms-addon-example --features native --bin typed-addon-server -- \
  /private/instance/addon.rpc /private/instance/operations /private/instance/key
```

Native client code uses ordinary methods generated from the service trait:

```rust,ignore
let transport = gcoms_rpc::local::LocalTransport::new("/private/instance/addon.rpc");
let handles = std::sync::Arc::new(gcoms_rpc::file_store::FileHandles::open(
    std::path::Path::new("/private/instance/pending"),
)?);
let client = GreetingServiceClient::new(
    gcoms_rpc::Client::new(transport, "greeting-example").with_handles(handles),
);
let greeting = client.greet("Ada".into()).await?;
let prepared = client.prepare_uppercase("hello".into())?;
// start_and_wait retains the opaque handle before transmitting.
let result = client.inner.start_and_wait(&prepared).await?;
client.inner.handles().forget(&prepared.handle)?;
// After a lost reply, use client.inner.resume(&prepared.handle). Never create
// another operation ID merely because a connection failed.
```

For browser Rust, build this library with `--no-default-features --features wasm
--target wasm32-unknown-unknown` and use wasm-bindgen's web output. `rust_greet`,
`rust_uppercase` and `rust_resume` demonstrate fetch and opaque browser handles.
The TypeScript equivalent is generated by `typed-addon-types` and
`@gcoms/rpc-codegen`, using the same method schemas.

Both browser clients call `/rpc`. A host must provide an authenticated same-origin
gateway that pins the `greeting-example` instance and the configured local socket
or GC peer. GChat's `exchangeBoundRpc` show that host boundary; do
not accept arbitrary upstream URLs or contact cards from browser requests.

The GC integration test (`cargo test -p gcoms-rpc --test gc_peers`) demonstrates
the same generated methods between two isolated persistent GC peers. Component
applications use `ComponentLink` with independently granted SDK routes.

The checked-in `browser/` example uses the same generated API from TypeScript:

```ts
import { RpcClient, BrowserHandles, httpTransport } from '@gcoms/rpc';
import { createGreetingClient, SERVICE, SERVICE_VERSION } from './rpc-api';
const rpc = new RpcClient(httpTransport('/rpc'), 'greeting-example',
  SERVICE, SERVICE_VERSION, new BrowserHandles(localStorage));
const greeting = await createGreetingClient(rpc).greet({ name: 'Ada' });
```

To qualify both clients against a real local native service in Chromium, from
the coms root (with `wasm-bindgen-cli` matching Cargo.lock and a Playwright
Chromium installation):

```sh
cargo build -p gcoms-addon-example --features native --bin typed-addon-server
cargo build -p gcoms-addon-example --no-default-features --features wasm --target wasm32-unknown-unknown
wasm-bindgen --target web --out-dir examples/typed-addon/browser/pkg \
  "${CARGO_TARGET_DIR:-target}/wasm32-unknown-unknown/debug/gcoms_addon_example.wasm"
cd packages/gc-rpc
CARGO_TARGET_DIR=/absolute/path/to/gcoms/target npm run test:browser
```

Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to use an existing Chromium binary.
The fixture starts its own private service and authenticated gateway, exercises
both clients, reloads after lost replies, and checks identity correlation and
authentication. It shuts down its children and deletes only its temporary files.
